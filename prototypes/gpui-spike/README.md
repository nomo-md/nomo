# GPUI 原型验证（2026-10-25）

验证 Zed GPUI 能否承载 Nomo 正文编辑的三个硬需求：中文 IME 组字、KP 断行可控性、10 MiB 级文档滚动，并用同一测试集测内存。原型只渲染 Markdown 源码文本，不做语义渲染，因此所有数字都是**纯文本渲染下限**，不能直接等同于完整编辑器。

## 结论

| 验证项 | 结果 |
|---|---|
| 复用 Rust 后端 | `src-tauri/src/text_document/piece_tree.rs` 经 `#[path]` 原样编译进原型，原有单测通过；`session.rs` 等与 Tauri 命令、`app_logger` 耦合，需先拆成独立 crate 才能复用 |
| 中文 IME（鼠须管，真实按键） | 组字下划线、空格提交、组字内退格删空后重输、Esc 取消、回车提交原文、按组字粒度撤销均正确，无崩溃；候选框锚点坐标经日志核对正确 |
| KP 断行可控性 | `layout_line` 暴露逐字形坐标，`paint_glyph` 可任意定位，两端对齐、避头尾、末行左对齐都已实现；普通段落塑形加 KP 单段最多 13 ms |
| 10 MiB 滚动 | 60 Hz 屏上匀速滚动帧间隔 p50 16.7 ms；本元素每帧 CPU p50 1.2–1.8 ms、p95 ≤ 3.1 ms；跳到 100% 能看到 `NOMO_END`；中部输入 60 字后全部撤销，全文逐字节一致 |
| 内存 | 空白 72 MiB，10 MiB 混合 98 MiB，50 MiB 纯文本 160 MiB（单进程，没有 WebContent） |

**主要问题：**

1. **超长单段落每键约 0.77 s**（`01_单段落1MiB`，KP；贪心约 0.13 s）。原型按段整段塑形，每次按键都重排整段。这是原型的实现问题，需要按句或按固定字节分块塑形，再做局部 KP。
2. **掉帧发生在本元素之外。** 匀速滚动有 0.4%–9.6% 的帧间隔超过中位数的 1.5 倍，最严重的是 5 MiB 混合贪心（87/902），但这些帧里本元素 p95 只有 2.6 ms。原因未定位，可能是字形图集上传、Metal 提交或系统调度，需要用 Instruments 采样确认。
3. **无障碍为空。** AX 树只有窗口按钮，正文没有任何可访问元素。GPUI 0.2.2 不为自绘元素提供无障碍支持，需要另接 AccessKit。
4. **冷启动偏慢。** 从进程启动到首帧 0.38–1.8 s，其中 `Application::new` 到 run 回调 0.19–0.67 s，开窗加首帧 0.2–0.4 s；读文件和建行索引合计 1–50 ms。这是冷进程口径，不能和应用内“打开文件到首帧”的数字直接比较。
5. **gpui 官方 `examples/input.rs` 的组字选区有越界 bug。** `replace_and_mark_text_in_range` 把新选区终点加上了 `range.end`，替换已有组字时会越界。调研中报告的 “IME 删空后重输 panic” 与此吻合，属于示例代码问题，不是框架本身的问题；原型已统一改为相对 `range.start` 计算。

## 实现要点

- **文档**（`src/text_document/mod.rs`）：复用持久化 PieceTree，原文只读，编辑只追加；行首索引在替换时局部拼接和平移；撤销记录逆操作。
- **排版**（`src/editor.rs`）：以源码行为段落，整段 `layout_line` 一次，按字形坐标求条目宽度并运行 KP，绘制时逐字形加上胶的累计伸缩量；布局缓存以“段落文本哈希 + 行宽 + 断行模式”为键，与行号无关，编辑后行号平移不会让缓存失效。
- **滚动**：锚点为“段落号 + 段内偏移”，只排版视口内的段落，跳转按行比例定位，到文末时向前夹紧。
- **IME**：只向输入法暴露光标所在段落，UTF-16 偏移以段首为 0，避免维护全文 UTF-16 索引；组字期间的编辑不进历史，提交时合并成一步撤销。
- **KP**（`src/kp.rs`）：标准活动节点算法，汉字间零宽可伸缩胶，拉丁空格胶，避头尾；无可行解时退回贪心。没有实现英文断词、悬挂标点和标点挤压。

## 未验证

- 只测了鼠须管，没有测系统拼音和第三方输入法；候选窗属于输入法进程，被截图过滤，位置只能通过日志核对锚点坐标，没有目视确认。
- Windows / DirectWrite、高 DPI 切换、ProMotion 120 Hz 都没有测。
- 掉帧根因没有定位；每个样本只跑了 1 轮，没有三轮中位数。
- gpui 用的是 crates.io 官方 0.2.2，落后于 Zed 主干；主干的 API 和行为可能不同。
- 原型没有语义渲染（表格、代码高亮、图片、公式、Mermaid），也没有导出、搜索、保存和多标签。

## 复现

```bash
cargo build --release
cargo test --release
./target/release/nomo-gpui-spike <file.md> [--greedy] [--bench] [--ime-selftest] [--exit-after <秒>]
./scripts/bench_corpus.sh <测试集目录>
python3 -I scripts/summarize_bench.py results/bench
python3 -I scripts/sample_memory.py ./target/release/nomo-gpui-spike <测试集目录> results/memory.md
./scripts/make_app.sh
```

快捷键：`cmd-k` 在 KP 和贪心之间切换；`cmd-up` / `cmd-down` 跳到文首 / 文末；`cmd-z` / `cmd-shift-z` 撤销 / 重做。设置环境变量 `NOMO_SPIKE_IME_LOG=1` 会输出输入法候选框锚点日志。
