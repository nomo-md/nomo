# KP 精细排版：实现与验收记录

本记录对应 2026-10-08 批准的实施计划。代码已接入主链路，**尚未达到 P0–P5 全部验收完成**。

## 启用与发布关卡

偏好设置 → 编辑器 → 段落排版，只保留“精细排版”总开关。开启后使用默认简体规则，标点压缩、行末悬挂和内容所需的行距调整一并生效。原有 `typographyProfile`、`typographyHanging` 用户配置不再读取；内核仍保留规则档案与悬挂参数供对照测试使用。

开发版默认关闭。`src/lib/typography/types.ts` 的 `DEFAULT_TYPOGRAPHY.enabled` 和 Quick Look 原生配置缺省值保留发布关卡；完成下述原生验收后改为默认开启。用户明确关闭的持久设置继续有效。未写入 Markdown 元数据。

## 代码边界

| 部分       | 入口与职责                                                                                                                                                                                                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 纯计算     | `src/lib/typography/knuthPlass.ts`：候选行计算、实际间距质量、两端/左对齐选择、松紧类别、连续断词、短尾行、强制断点、共享搜索预算。与 DOM 无关。                                                                                                                                                           |
| 语言规则   | `rules.ts`、`hyphenation.ts`：Unicode 断行机会、简繁标点策略、字素边界、中西文视觉空白、显式软连字符及美式英语 Liang 候选。                                                                                                                                                                                |
| 测量       | `measure.ts`：真实字体连续前缀测量，字框空白测量，公式/图片/行内代码尺寸与基线。                                                                                                                                                                                                                           |
| 渲染与坐标 | `renderPlan.ts`、`positions.ts`：视觉行、间距、边缘调整、原文位置和视觉位置的边界倾向。编辑器继续使用 ProseMirror 原生 DOM 坐标映射。                                                                                                                                                                      |
| 调度       | `solver.ts`、`typography.worker.ts`：内联 Worker、请求编号、错误/超时回退。主线程测量，Worker 求解。                                                                                                                                                                                                       |
| 编辑态     | `editor-core/plugins/typography.ts`：约 150 ms 空闲调度、组合输入与拖动选区保护、导航期间延后待完成的重排、段落缓存、过期结果丢弃、Decorations。已排版段落的普通左右键按语义文档字素移动；格式边界及行内对象保留原有优先处理。`TypographyBreakNodeView` 只负责源码换行的视觉投影，相同投影不重复替换 DOM。 |
| 只读       | `dom.ts`：预览、Quick Look、导出共用；保留语义副本，宽度/字体变化后重排，关闭时恢复。                                                                                                                                                                                                                      |
| 导出       | `ProseMirrorEditorCore.getExportHtml()` 从文档序列化，保留必要的图表/代码渲染快照，重新生成公式。导出清理装饰，再嵌入运行时、Worker 和 KaTeX 字体。                                                                                                                                                        |
| PDF        | Windows 与 macOS 按纸张方向和左右边距计算版心，调用 `__NOMO_PREPARE_PRINT__(widthMm)`，等待字体、图片及最终排版。就绪失败或超时不能打印为成功。                                                                                                                                                            |

普通单换行保留在文档中。精细模式将其投影为上下文所需的空白；硬换行仍为强制断点。编辑态复制与保存继续从语义文档序列化，不复制视觉断点。排版事务不改变 dirty、正文修订或撤销历史；会使滚动同步几何缓存失效。

`linebreak@1.1.0` 提供 Unicode 13 的 UAX #14 数据；`Intl.Segmenter` 提供运行环境的字素边界。因此不能宣称最新 Unicode 版本的完全一致性，也不以复现 TeX 输出作为验收标准。其他文字、复杂 HTML、无法容纳的不可拆对象及预算超限保留原生段落布局。

## 初始预算与已知工程边界

- 测量约每 8 ms 让出主线程；单段超过 20,000 个 UTF-16 单元或约 1,500 ms 测量预算时回退。
- 搜索默认最多 100,000 个候选、约 100 ms；检查预算时整段回退，不返回半段文本。
- Worker 请求 5 s 超时；导出资产等待 20 s、排版稳定等待 30 s。失败不记录正文。
- 未改动段落复用已发布装饰；字体或几何失效时重新测量。可见段落优先计算，按约 16 ms 的发布间隔提交完整段落，未处理段落暂时保留原布局；中途取消的未发布结果不会进入缓存。
- 简繁档案目前提供基础禁则、成对省略号/破折号、连续标点与边缘压缩。大量不同字体、繁体标点风格和高行内对象仍需视觉样例扩充。
- 只读适配器覆盖段落、直接含行内内容的列表项和单元格；混有嵌套块的复杂 HTML 使用现有结构，不强行改写。表格列或 HTML 指定居中、右对齐时保留原生对齐布局。
- 原文不被改写已经有测试；原生输入法、跨视觉行光标/选区行为不能由 jsdom 或合成 composition 事件代替。

## 间距质量与精细左对齐（2026-10-08）

参考 Telari 还原文档中的参数分类与对齐策略，保留现有 TypeScript、Worker、ProseMirror 和单一总开关。以下数值为 Nomo 当前内部策略，不是 Telari 默认值。

- 汉字间自然间距仍为 0；可伸硬上限由 `0.35em` 调整为 `0.1em`，舒适上限为 `0.05em`。不通过负汉字间距挤压字形。
- 中西文自动空白的自然宽度仍为 `0.125em`，可伸/可缩硬上限均为 `0.0625em`，舒适调整为 `0.04em`。原文空格和西文软换行空白按实际宽度分配：最多增加 50%、缩小三分之一，舒适调整为 25%；不同空白使用相同分配权重。
- 行评分同时检查总伸缩比与每个实际间距相对舒适范围的调整量。两端对齐容差为 100，局部大空隙不能被整行的总容量掩盖。
- 宽度小于正文的 `20em`，或行内代码宽度占段落自然宽度至少 35% 时，直接使用 KP 左对齐。其余段落先尝试符合间距质量要求的两端对齐，无解时在剩余时间与候选预算内求解左对齐；预算超限和不可容纳对象仍走原有原生回退。
- 左对齐保留自然间距、标点规则、视觉断点及全段搜索，评分考虑非末行的剩余空白。尾行最小期望宽度取 `min(行宽 × 12%, 正文字号 × 4)`，惩罚为 500，避免为了拉长宽栏末行而制造首行大空隙。
- 就绪段落通过 `data-kp-alignment` 标记 `justify` 或 `ragged`，供开发诊断使用。编辑与只读使用同一计算路径，复制、保存和撤销继续从原文语义模型处理。
- 编辑器中 KP 就绪段落的选区底色以主题强调色 70% 与正文底色 30% 预混合为不透明色，避免压缩间距时相邻半透明背景重叠形成深色竖条。选区范围和排版几何不变；非 KP 段落继续使用原有背景。
- 自动英文断词使用固定版本 `hypher@0.2.5` 与 `hyphenation.en-us@0.2.1`，只添加带真实字体连字符宽度的候选断点；不插入源码软连字符。字典和计算代码随构建打包，离线导出不请求网络。仅处理 8–80 个 ASCII 字母的普通小写或首字母大写单词，排除代码、链接、网址、邮箱、带数字/下划线的标识符和驼峰词。显式标注其他语言的文本不使用英语字典；未标注语言的 ASCII 单词按美式英语处理，不宣称自动语言检测或多语言断词支持。

依赖新增两包，用于复用现有 Liang 引擎和英语模式，避免自行维护算法及字典。授权说明见 `public/THIRD_PARTY_NOTICES.md`，随主应用与 Quick Look 构建复制，离线导出运行时内嵌同一说明。本轮不改变默认关闭的发布关卡；真实字体、页面和原生输入法仍须独立验收。

## 行宽、字号与缩放的持续精排

- 主编辑区调整期间保留已显示的 KP，CSS 尺寸立即跟随输入；新断行由各编辑器独立追补，不等待整个视口或比较文档计算完。停止操作时继续补齐剩余段落，不再触发一次原生换行到 KP 的模式切换。正文、软换行投影、选区和撤销历史保持原有语义。
- `interaction.ts` 管理窗口内来源 token、`preview/settling/idle` 状态、generation 和实际尺寸的 `geometryRevision`；`preview` 为交互活动阶段。滑块从第一次有效 input 开始，在释放、取消、键盘松开、失焦或销毁时结束；缩放滑块直接应用数值，按钮与 Ctrl+滚轮保留原时长动画。滚轮、按钮和跨窗口设置更新仍使用 150 ms 静默收束，期间可以更新 KP；替换动画接续同一活动阶段。
- 尺寸变化前各可见语义编辑器同步捕获阅读锚点，写 CSS 后恢复并通知订阅者。取消冻结目标、全窗就绪屏障和旧批次回写 CSS；KP 关闭、隐藏编辑器、组合输入或拖选均不阻止控件改变尺寸。各编辑器只负责自己的装饰发布和最终完成信号。
- 按段读取当前 CSS 的标量字体、逻辑行宽和对象尺寸，异步测量使用该快照；不再临时切换目标 CSS，也不在一个输入帧内同步采样整屏。交互只计算视口和上下各 25% 屏高、最多 160 CSS px 的边缘缓冲，按帧递进发布；缓存段落的连续扫描累计 6 ms 后让出任务。停止后优先整批发布可见区域，其余段落后台按帧更新。
- 宽度变化只记录待处理布局，不取消在途文字测量；文档、源码显隐、字体资源和对象几何变化仍使绑定失效。每段在测量后、求解后及提交前重新校验当前签名，过期尺寸结果不发布。独立布局请求版本覆盖侧栏、双栏分隔、窗口尺寸及主动滚动，避免在途新请求被错误标记为完成。完整排版已完成、无行内对象且编辑器逻辑宽度与字体签名保持不变时，纯 zoom 复用断行并跳过整篇扫描与求解。
- 每个编辑器持有独立的文字测量 LRU：最多 128 文本组、32,768 字素、262,144 键字符。缓存完整 shaping 组的前缀宽度、字素指标和连字符宽度，字号、字体、字距或 shaping 参数变化时重测；宽度及 zoom 变化可复用文字度量。每轮重新绑定当前 DOM，图片、公式及代码框的尺寸仍单独采样。字体加载完成、排版选项改变或编辑器销毁清理缓存。
- 纯文字 KP 包装复用其语义父级字体和可见性快照；自带语义/字体/display 属性、原子节点及只读包装仍走常规测量。装饰绑定通过位置索引查找，只替换实际变化的段落，保留其余 Decoration 与 DOM；后台提交不再反复构造全文装饰集。
- CSS 变化和装饰发布前在当前视角捕获 ProseMirror 文档位置与屏幕纵坐标；Ctrl+滚轮使用鼠标位置，其余操作使用视口中心。异步计算期间的主动滚动不会恢复旧阅读意图，双栏跟随继续交给现有同步控制器。组合输入和正文拖选期间不替换装饰 DOM；失效结果不发布，取消不生成 fallback。
