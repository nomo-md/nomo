# 真人写作测试方法

更新：2026-11-02。用于 Nomo 原生编辑器的真实键鼠验收；逐项用例见 [基础写作清单](basic-writing-checklist.md)，功能专项补充见 [编辑器恢复清单](editor-restoration-checklist.md)。

## 输入规则

1. **每一个字符、每一个符号都单独输入。** 使用真实按键事件；`1.` 必须拆成 `1`、`.`，`- [ ] ` 必须拆成 `-`、空格、`[`、空格、`]`、空格，三个反引号也必须分别输入。不能用整串输入、剪贴板注入、直接写文件或恢复已有文档代替从零写作。
2. 输入一个语法符号后检查当前画面，再输入下一个符号；重点保留未完成前缀、未闭合标记、空列表项和空块。普通正文也逐键发送，可在一个短词后检查。不能仅检查成品 Markdown 的渲染。
3. 空格、Tab、Enter、Shift+Enter、Backspace、Delete 和组合快捷键使用对应按键事件。工具若只能粘贴文字，相关键盘输入项记为阻塞，不能标为通过。
4. 中文使用真实输入法逐个拼音键、候选选择、提交和取消；单字粘贴也不算 IME。需要记录候选/组字是否实际出现。
5. 剪贴板是独立用例：先逐键写出内容，再通过应用的复制、剪切和粘贴验证；报告明确标注粘贴。系统对话框路径也逐键输入。只允许在磁盘准备图片等非正文资源。

## 固定被测对象

- 记录日期、分支、提交、工作区改动、Release 构建命令、可执行文件 SHA-256、源码输入哈希、进程 ID、数据目录和日志位置。
- 使用独立数据目录和测试文档目录，复制已核实的 Release 二进制。测试时不替换该二进制；修复后复测应建立新的构建记录。
- 记录主题、窗口实际尺寸、DPI/缩放、输入法、编辑模式和测试资源。无法获取的环境值写“未取得”，不推测。
- 原版兼容行为先确定参考版本和具体预期。现有单测的断言不能自动充当产品需求；有序/无序列表切换按用户确认的整组父列表规则验收。
- 本方法不授权改动用户正文。异常样本、日志和保存检查点放在本轮 `.artifacts/<任务>/` 内。

## 按写作流程执行

1. 新建空白文档，确认焦点，写短段落；移动和选择，修改、删除，撤销和重做。
2. 逐键写标题与行内格式，经过每个未完成状态，再补齐正文和结束符；从格式内外移动光标继续写作。
3. 创建列表，续项、缩进、嵌套、切换类型、任务勾选、提升和退出；覆盖末项末尾和空子项。
4. 插入引用、代码、表格及基本对象，编辑正文，测试块前/块后继续输入和删除恢复。
5. 查找替换、复制剪切粘贴，切换源码/语义/双栏和标签，再核对当前内容、选区与阅读位置。
6. 保存、关闭、重开，独立读取磁盘文件核对源码。持久化结果和界面行为分别记录。

每个案例都明确起始文档、模式、焦点、光标/选区、逐键顺序、预期和观察。长度使用最小可辨认样本，减少无关输入，不省略触发过程。每类基础行为至少执行一条完整路径；失败后保留最小样本，继续能独立执行的其它案例。

## 每一步检查什么

| 检查对象 | 判定内容 |
|---|---|
| 正文 | 新字符出现在目标位置，无丢字、重复、误替换或残留标记 |
| 光标和选区 | 留在预期行/字符边界；格式隐藏、空项和空块仍有可输入位置 |
| 结构 | 列表层级和类型作用范围、段落/软换行、块边界及格式完整 |
| 历史 | 一个结构动作的撤销/重做恢复相应内容和位置；不臆定普通连续字符的分组策略 |
| 持久化 | 实际保存内容与界面相符；重开没有丢失、额外标记或结构改变 |
| 体验 | 记录确实观察到的跳动、卡住、刷新后才更新、闪烁和短暂错位，并说明观察边界 |

动作前先确认焦点。若按键无效且焦点不明，记为无效尝试，重新定位后重做；不得把尝试次数当成有效测试次数。光标闪烁或空白位置无法可靠看清时，可在独立测试页输入一个可撤销字符，核对真实插入位置后撤销恢复；不能只凭鼠标坐标推断落点。异常应从已知初态重复至少一次，分别记录分子/分母；无法重现时保留观察，不能擅自关闭。

## 证据与结果

- 状态仅用：**通过、失败、部分、阻塞、未测**。通过仅覆盖记录的起始状态和动作；部分须列出实际做过和未做的子项，阻塞须写具体工具/产品原因。
- 截图和操作日志遵循桌面工具能力与限制；只能内联截图时写明证据在工具历史，不能编造落盘图像。记录可追溯的案例 ID、动作和样本文档。
- 静态截图不证明不存在短暂闪烁，调用工具耗时不等于应用延迟。若有程序内帧采样，说明指标是 CPU 侧绘制/按键到随后绘制的统计及采样边界，不称为完整用户端延迟或三轮性能基准。
- 文件哈希相同只证明持久化字节一致，不证明光标、布局或交互通过。命令/解析单测通过也不能替代真实键盘入口和视觉验收。
- 每个缺陷包含严重程度、构建、案例、初态、逐键步骤、预期、实际、有效复现次数、保存样本和影响。根因分析注明“代码支持”或“待确认”，不把猜测写成已确认原因。
- 清单中每一行必须在本轮报告出现；没有结果的行默认未测。汇总数量从逐项结果计算，不能将一次混合操作概括为全功能通过。
- 收尾保存测试文档，通过 UI 正常退出隔离实例；复核二进制/源码是否改变、文件内容、错误日志和进程退出状态。测试报告与修复报告分开，发现问题不代表已经修复。

## 每轮报告字段

报告至少包含环境和构建、逐项结果表、可复现缺陷、体验观察、未测/阻塞原因、输入方式合规说明、保存内容核对、退出情况及下一轮复测入口。原有专项清单的未完成项继续保留，不因本轮基础写作通过而整体勾选。
