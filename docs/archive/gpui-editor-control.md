# GPUI 窗口编辑控件：开发入口、契约与验收状态

更新：2026-10-26。工作分支 `gpui-editor`，开发基线 `5b03a716b7df2396f3a8bb6c8e2eefe739a10f72`。

这是开发中的内部控件，**尚未完成 Nomo 原版功能及视觉等价验收，尚未替换默认编辑器**。普通 GPUI 页面仍使用 `EditorView`；显式启用开发入口后使用 `EditorControl`。下面分别记录控件实现、真实会话连接和未完成工作。

## 开发入口

在仓库根目录运行：

```powershell
cargo build --manifest-path src-gpui/Cargo.toml --locked --release --target x86_64-pc-windows-msvc --features editor-control-demo
& ./src-gpui/target/x86_64-pc-windows-msvc/release/nomo-gpui.exe --editor-control-demo
# 真实文件入口（当前为单文档宿主）
& ./src-gpui/target/x86_64-pc-windows-msvc/release/nomo-gpui.exe --editor-control D:/path/document.md
```

`--editor-control-demo` 打开内置样本，`--editor-control` 打开真实文件；两者使用原版 Rust `MarkdownDocumentSessionManager`。真实文件入口已增加 GPUI 连续滚动、邻近窗口挂载/预取/回收连接，尚未完成连续窗口的桌面验收。它不在已有未保存标签上切换编辑实现，也未替换默认 `Workspace`。没有启用 feature 时，不链接开发宿主的 SQLite、会话、Emoji 网络加载器等可选依赖。

控件使用 GPUI 0.2.2 的公开 `Window` 文字塑形、输入和绘制接口，未修改 GPUI。文字布局和绘制仍复用当前 GPUI 工程已有代码。

## 数据流与模块

```text
宿主选择范围、调用原版会话读取 DocumentWindow，提供 WindowContext
  → ParsedWindow：原文共享引用、解析事件、语义节点、真实源码范围
  → EditorControl：语义/源码布局、命中、选区、组字、局部对象草稿
  → ControlEvent：事务、导航/剪贴板意图、几何、资源需求、生命周期
  → 原版会话提交/撤销/保存，宿主确认并回送最新窗口
```

| 模块 | 实际职责 |
|---|---|
| `editor_control/protocol.rs` | 原版 camelCase 窗口/事务字段、全局选择、版本、上下文、状态与事件 |
| `host.rs` | 当前窗口的乐观投影、串行确认队列、失败保留/重试、外部范围重基、回收门禁；不拥有撤销历史 |
| `parse.rs`, `dialect.rs`, `template_projection.rs` | 解析已提供的文本、行内真实标记、来源明确的空模板投影、引用上下文、Details/Front Matter、空段落锚点 |
| `mapping.rs`, `source_view.rs` | UTF-8/UTF-16/显示映射、原文换行、源码行和高亮上下文 |
| `interaction.rs`, `commands.rs`, `inline_commands.rs`, `list_commands.rs` | 交互保护、局部显隐、格式/结构源码补丁、嵌套列表与任务项规则、选择映射 |
| `view.rs`, `paint.rs` | GPUI 输入、组字、布局就绪门禁、键鼠、选区/光标、菜单、几何报告 |
| `table.rs`, `html_table.rs`, `table_widths.rs` | GFM/原版 HTML 表格、已有合并关系、行列/表头/对齐、列宽分配、局部横向滚动 |
| `widgets.rs`, `object_ui.rs`, `image_properties.rs` | 对象草稿与确认/取消；图片地址/替代文字/标题/宽度/对齐属性；HTML 原子节点载荷和表格行列数量编辑 |
| `menu.rs`, `emoji.rs` | 共享命令入口、斜杠/右键/选区菜单、完整 Emoji 元数据的检索索引 |
| `resources.rs` | 读取宿主共享资源状态并报告需求，不访问文件或建立独立解码缓存 |
| `native_port.rs`, `session_window.rs`, `session_actions.rs`, `demo.rs` | 原版 Rust 会话与真实文件宿主连接、原索引范围/引用查询、全局剪贴板/编辑、原版历史、完整快照保存、关闭流程 |
| `viewport_model.rs`, `viewport_ui.rs`, `resident_budget.rs` | GPUI 占位高度/阅读位置、连续滚动和按需挂载、活动输入移交、回收门禁、共享驻留登记；不拥有正文或语法索引 |

`markdown/render.rs` 的 `layout_parsed` 消费解析结果；旧 `layout_block` 保留原编辑器入口。`layout.rs` 按 Unicode 字素选择字体，避免拆开 Emoji ZWJ 序列。

为直接复用原版服务，仅把原有纯代码移到 `markdown_encoding.rs`、`text_document/native_types.rs`、`file_system/atomic_write.rs`、`emoji_catalog/native.rs`，原 Tauri 入口继续转发；空模板类型和纯位置映射共用 `markdown_templates.rs`，来源持久化纳入原版 `markdown_session`/`markdown_history`；`text_document/native.rs` 是开发宿主的原版服务入口。没有复制会话实现，没有新建加载器或全局索引。

## 宿主连接约定

1. 提供文档/窗口身份、修订、宿主 `view_generation` 和全局字节范围。文本长度必须等于范围长度。`WindowContext::Complete` 是宿主对独立语义边界的明确保证，不能仅因为读取成功就设置；缺失上下文返回 `NeedsContext`。
2. `WindowContext::Resolved` 可携带引用定义和祖先引用/列表/Details 上下文。控件不回读全文。当前尚未覆盖任意结构中间切片，见上游缺口表。
3. 挂载后保持 `Preparing`，目标宽度和几何就绪后才允许输入。使用 `set_readonly` 控制权限。宿主修订、视图代数和本地 `projection_generation` 分开管理。
4. `Submit` 使用原版 `baseRevision`、`operationId`、`historyGroupId`、全局源码编辑与前后选区。一次只发送队首；后续输入可继续进入局部投影。确认用 `acknowledge(operation, revision)`，最后一笔确认后用 `verify_authoritative` 核对宿主窗口，自己的确认不重建输入控件或结束组字。同内容输入不排队为新事务，以免原生无操作确认被误判为旧修订。
5. 提交失败调用 `fail`，保留投影及待确认事务。`retry` 重用相同 operationId。宿主内容与投影不一致会保护窗口，不能通过隐藏/卸载悄悄丢弃输入；显式冲突恢复接口仍待补齐。
6. 窗口外、互不相交的修改使用 `rebase_outside`，只移动全局锚点。相交编辑和跨窗口选择须由宿主给出结果，不能猜测偏移。调用 `update_window` 前必须解除组字、草稿、拖选及待确认输入保护。
7. `hide` 释放布局/菜单/几何，`restore` 重新等待布局；`prepare_unmount` 检查保护状态，`detach` 释放视图引用。显式丢弃必须由宿主关闭流程决定。正文、历史、快照和保存继续属于会话。
8. `LayoutReady`、`HeightChanged`、`Geometry` 带 `LayoutStamp`。几何使用 GPUI 逻辑像素及应用窗口坐标，包含可见区域、源码锚点/纵坐标、光标、可见选区。宿主据此修正滚动；控件只处理表格内部横向滚动。
9. 跨窗口选区、全选、剪贴板、导航和历史交给宿主。局部和全局剪切均先写剪贴板并读回核对，失败保留正文。真实文件宿主使用单个原版快照分段读取全局选区，并接入普通替换/删除和锚点定位；跨窗口组字、结构命令与搜索界面尚未接通。
10. 保存使用 `NativeWindowPort::save_to` 的会话快照，不使用 `ParsedWindow.source` 作为全文。`ResourceDemand` 由宿主分发到共享 ImageStore/EmbedStore，Emoji 加载也位于宿主。
11. 真实文件宿主通过原生结构索引分页获取分组元数据，和 Web 宿主共用 `viewportPolicy.json`、`windowingLimits.json` 的原有默认值。仅活动窗口开放输入；其他已挂载窗口在焦点移交且旧窗口交互保护解除后开放编辑。视图数、源文字节和原生布局估算成本登记在共享预算中，不能通过裁剪历史回收空间。
12. 连续窗口实现目前等待原生索引就绪后取得分组元数据；临时元数据和组目录各有 32 MiB 预算，超出时保留当前窗口并报告受限。原生布局额外以 64 MiB 估算值限制可选预取；该值不是实测进程内存上限，也不等价于原版 DOM 节点预算。图片和公式仍使用 GPUI 全局资源缓存。

空模板协议是可选扩展：事务的 `templateUpdate.add` 只登记显式命令产生的模板；窗口的 `inlineTemplates` 返回当前范围相交的来源记录。记录含格式、开闭标记位置与 HTML 表达方式，所有位置均为全局 UTF-8 字节。旧客户端省略字段仍沿用原协议，旧历史/恢复文件的缺省值为空。普通文字输入消耗被触及的模板来源；模板格式操作允许保留内层/外层来源，原版历史负责撤销重做和恢复。跨出窗口的来源必须返回“需要上下文”，不能猜测或忽略。组字取消仅恢复当前组字开始前持有的来源，并随普通事务提交，不扫描正文推断模板。

## 定向检查与语料


## 资源与后续开发顺序

控件新增常驻状态属于已挂载视图：当前 `Arc<ParsedWindow>`、当前布局、选区/临时显隐/表格横移、待确认输入；对象打开时才创建源码草稿子控件。文档正文和磁盘历史仍在原版会话中。Emoji 索引共享弱引用，有 16 MiB 索引预算；元数据沿用原版哈希、下载大小、超时与缓存校验。对象关闭和窗口隐藏/销毁释放对应引用，已删除表格/Details 的临时状态被清理。原版会话另外持有稀疏的空模板来源位置；仅来源变化时随现有磁盘历史记录前后状态，64 MiB 历史热缓存按完整序列化记录计量。窗口只持有相交来源，组字仅临时保留有关来源位置；解析空模板时临时分配等长占位片段，原文仍保留在共享引用中。大量同时未使用模板的元数据成本尚待专项测量。

仍需收敛的实际成本：每次输入解析当前已加载窗口；整个窗口布局仍常驻，绘制按可见范围裁剪；表格全局列宽需要扫描完整给定结构；HTML/Details 解析和引用上下文存在重复工作。当前估算不是进程私有驻留、私有提交、JS 堆或 GPU 使用量，不能相加替代实测。
