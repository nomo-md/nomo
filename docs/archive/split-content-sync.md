# 双栏内容同步

双栏保留各自的自然排版，不通过逐块 spacer、共同总高度或循环纠偏实现等高。优先保证用户正在操作的一栏稳定，其次保证内容对应，最后才是视觉对齐。没有新增持久化模式或设置。

## 当前行为

- 滚轮、触控板、滚动条和阅读翻页决定滚动主栏，与编辑焦点独立。主栏视口 30% 处的内容位置在相邻可靠锚点间插值，换算到另一栏的 30% 位置。每帧最多写入一次跟随栏，连续滚动没有平滑动画。
- 主栏到达真实首尾时，跟随栏也定位到首尾。中间位置只限幅，不补白。短文档保持自然布局。
- 输入、点击或键盘移动光标时，对应位置在另一栏 15%～85% 可见区域内便不滚动，否则定位到 30% 附近。不显示顶部活动栏标识或另一栏的光标位置标记，也不移动另一栏光标、选区或焦点；正常输入光标保留。
- 手动滚动优先于旧光标意图；下一次明确编辑操作才重新启用光标辅助。选区拖动与组合输入期间暂缓处理，结束后只处理最新意图。
- 拖动分栏时暂停跟随，结束后重新测量。异步图片、字体、图表、代码展开和缩放只使几何缓存失效，不恢复主栏的旧位置。
- 模式和标签切换取消旧任务。大纲保留原有导航，显式跳转会指定当前编辑栏为主栏。参考线按钮显示30%位置，默认隐藏。

## 代码归属和一致性

| 模块 | 职责 |
| --- | --- |
| `scrollSyncMapping.ts` / `markdown.ts` | 使用现有 tokenizer、实际 token handler 和同一图片预处理来源，记录真正创建的节点与原始行范围；不依赖文字搜索或两边块数相同 |
| `ProseMirrorEditorCore.ts` | 独立内容修订与渲染修订；源码刷新和语义序列化待完成时暂停发布；对照实际文档确认节点，提供只读几何、光标和合成 EOF |
| `markdownScrollSync.ts` | 主栏/意图状态、单帧调度、区间插值、接管取消、安全区与边界；唯一跨栏滚动写入入口 |
| `markdownScrollSyncWorkspace.ts` | 核对文档身份及源码/语义文本一致，转换各自滚动坐标，监听输入/布局 |
| `EditorWorkspace.svelte` | 正常视口最小高度和各栏独立尾部阅读空间；提供工作区生命周期与拖动状态 |

选区事务不重建内容映射。布局变化只清除几何缓存；滚动查询缓存并测量必要的相邻锚点。锚点不写入 Markdown、节点持久化属性或撤销历史。源码仍遵守原来的语义刷新节流，语义编辑仍遵守原来的 Markdown 序列化时机。

内容就绪检查兼容 CRLF、LF 和两者混用：仅在比较副本中将 CRLF 转成 LF，不改原始 Markdown 或保存格式，也不忽略空格及其他正文差异。比较结果按文档身份、修订及三方文本缓存；源码单独更新完成时会重新核对，滚动帧不重复规范化全文。

切栏与外部内容刷新统一经过源码编辑器的更新入口。按 CodeMirror 的逻辑行规则比较后，内容相同不产生事务；内容变化先匹配未改动行，再按完整 Unicode 字符细分变化区间，一次事务提交多处差异。首次编辑可能同时规范化文档前后的 HTML、表格和列表，不能把首尾差异之间的正文整段替换，否则会丢失 CodeMirror 的视口锚点。差分有工作量上限，超出时只合并尚未匹配的区间。真正切换文档仍重置源码历史。同步同时等待当前源码内容的测量完成，旧修订的测量回调不能提前解除等待。

表格序列化保留反斜杠，并使用足够长的反引号包裹行内代码；不能因丢失表格内字符而使重新解析后的节点位置与语义文档错位。相关回归直接读取完整 `README.md` 和 `sample.md`，验证首次编辑前后未改动源码位置的映射以及复杂节点后的锚点完整性，不写入这两个文档。

编辑时仍使用 15%～85% 的光标可见区，不强制两栏同一水平线；手动滚动后恢复 30% 参考线映射。

CodeMirror 的行位置、padding 和内容高度带有缩放，源码句柄统一除以 `scaleY` 后再与 `scrollTop` 换算；逆向查行则乘回该比例。源码大纲跳转使用实际换行后的行位置，不再使用“行号×固定行高”。

旧 `markdownBlockAlignment`、语义 decoration 和源码 spacer 接口及测试仍保留，但不再从双栏运行路径调用。

## 精度与降级边界

标题、段落、列表容器/列表项/内部段落、引用、Callout、表格行及普通代码逻辑行提供对应边界。重合源码起点优先选可定位的内部节点。Front matter、空白和 EOF 有独立标识。

长段落在边界之间近似连续换算；图片、公式、Mermaid、复杂 HTML 只保证所属块对应。折叠、隐藏、局部滚动的代码与未提交草稿只按可见块边界定位，不自动展开或滚动内部容器，也不改变草稿提交时机。

局部节点无法确认时使用附近可靠的父块/内容边界；完全无可靠锚点时保持当前位置，不退回同 `scrollTop` 或全文百分比。已渲染且不触及边界的可靠区间可用约4 CSS px作为验收参考，不会据此启动生产环境的重复纠偏。

复杂块规范化造成节点长度偏移时，通过 ProseMirror 结构差异确认未改动的前后缀，并重新验证目标节点的类型、属性和内容后换算后缀锚点位置。跨越不一致区间的节点仍降级，不用块数或文字搜索猜测对应关系。

开发环境可在 `.editor-grid` 的 `data-sync-leader`、`data-sync-status`、`data-sync-revision` 查看主栏、等待/跟随原因和修订；不记录正文、不逐帧打印日志。

回归入口：`markdownScrollSync.test.ts`、`markdownScrollSyncWorkspace.test.ts`、`scrollSyncMapping.test.ts`、`EditorWorkspace.test.ts`、`MarkdownSourceEditor.test.ts`，以及既有代码/公式/图表/编辑器核心测试。工作区回归使用真实编辑器和事件，覆盖换行格式、不同步时暂停及修订恢复；几何使用模拟数据。真实换行、字体缩放和资源加载效果仍以实际页面验证为准。
