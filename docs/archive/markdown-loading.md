# Markdown 统一会话迁移与验收

主应用的 Markdown 入口已默认装配统一会话。打开、新建、示例、旧草稿导入及恢复后，标签只保留会话身份和元数据；语义与源码视图按窗口挂载。本文区分代码接入、自动检查和分批原生验收，未覆盖场景不能由既有结果代替。

### 结构块挂载参数与诊断

`mountWindow.ts` 管理稳定分组和滚动需求；分组最多 32 KiB / 64 个完整块，发布后不因视口变化或索引追加扩组。上下基础缓冲各 3 个视口高度，前进方向依据近期准备耗时 P95 和平滑速度扩展至最多 6 屏，回收边界再远 3 屏；300 ms 静默后收缩。保留带不主动创建视图。每批协作预算 4 ms，单组超时仅记录，不能宣称可抢占。

32 个视图 / 1 MiB 窗口源文为可选驻留的软预算，达到压力条件先清理远处保留内容并暂停额外扩展；可见区、基础缓冲和受保护编辑优先。窗口源文字节不是进程内存估算。宿主布局 LRU 同时限制 2,048 条与 2 MiB 估算字节，保存纯高度、列宽和约束，不保存 DOM、编辑器或回调；缓存依赖内容、引用定义、正文宽度、字体几何、缩放和加载资源。宿主销毁释放全部缓存。

`MarkdownViewportHost.diagnostics` 提供累计创建/销毁、重叠 DOM 移动、布局测量、列宽发布与恢复、锚点修正、准备超时、挂载峰值及缓存统计。诊断不在每次滚动时遍历全文 DOM。首屏或远跳超过 100 ms 且目标区域仍未挂载时显示准备提示；未就绪结构不挂载临时源码，确实无法安全语义化的结构显示局部提示。源码与语义投影共用会话历史。

表格布局快照按同一内容版本内的表格序号保存已完成结果，未完成的远处表格不会阻止邻近表格缓存。预备测量使用真实编辑滚动容器作为 IntersectionObserver 根；有效列宽在窗口插入 DOM 前恢复。阅读锚点复用块级位置索引，避免滚动时进行逐字符源码坐标转换。

编辑导致块组替换时保留用户的编辑焦点意图，等新视图首帧启用编辑后再恢复焦点。用户点击或聚焦其他控件、隐藏宿主后取消恢复，避免异步挂载抢焦点。

### 首屏语义预览与编辑就绪

所有 Markdown 仍共用一个会话及渐进结构索引。小文档在原阈值内逐步挂满，大文档按原规则挂载可见区和缓冲区；逐步挂满是最终挂载状态，全文索引完成不表示全文 DOM 已挂载。稳定块组、封口规则、3–6 屏预取、回收滞回、窗口预算和布局缓存均未调整。

第一阶段取消普通等待区域的源码回退：活动语义视口缺少安全结构时提出可撤销需求，只提升后续扫描批次，安全结构可用后降回后台优先级。每批仍让出执行机会；远跳沿既有安全检查点和扫描链路推进，不启动第二套解析。隐藏、导航变化、修订变化和关闭撤销过期需求，同一文档的宿主共享索引。

已确认边界的完整块挂载后先处于只读状态，复用 PM 初始挂载生命周期解除门禁。屏内准备也遵守原有 4 ms 批次预算，先发布已准备的完整组，不等整屏准备完毕；单组解析仍不可抢占。调用窗口时须在 DOM 接入宿主后执行 `activate()`；`whenReady` 表示初始视图生命周期结束，实际写入仍检查应用只读、映射过期、事务、历史、故障及关闭状态。权限切换不重建 PM、正文 DOM 或源文映射，不增加正文事务和撤销步骤。空白新文档不增加预览等待。只读本身不减少解析或挂载成本，不能由此宣称加载更快。

第二阶段将 raw 结构映射为局部提示。提示保留结构身份和全局字节范围，不缓存结构原文；其实际高度进入原测量、缓存及锚点流程。源码入口沿应用模式协调定位，双栏定位源码侧，组合标签沿共享模式切换，不改变默认模式偏好。结构内部的精确目标字节在源码与语义往返时保留。提示不进入正文、历史、复制、保存、搜索或导出快照。

定位等待、源码宿主延迟创建及隐藏期间，用户转向其他控件会撤销旧焦点意图；源码目标字节仍保留。过期模式请求通过会话修订和目标代次失效，不能在返回语义模式后重新切回源码。

双栏首次创建源码宿主时接续现有阅读目标，正文安装前被空容器截断的滚动位置在安装后恢复；被动挂载不能切换活动栏。组合标签的显示就绪通知分别发送到有效成员，避免非活动栏停留在动画隐藏状态。统计/lint 的延迟快照任务在关闭、替换和活动标签变化时撤销，执行与回调仍校验修订及运行时身份。

`MarkdownViewportHost.presentation` 与应用会话 `presentation` 提供当前宿主的模式、修订、目标代次、阶段及覆盖类型。`timings.preview`、`editable`、`covered`、`stable` 和 `indexed` 均以会话打开为时间原点，`started` 标识当前目标开始时刻；仅保留当前记录。`coverage` 区分 pending、semantic、mixed、source，受限提示仅计入混合覆盖，不计入语义正文预览或可编辑。布局连续 300 ms 无可见几何变化记录 stable，不以全文索引结束作为前提。这些是代码生命周期代理指标，实际画面和真实输入就绪仍需原生测量。

增量资源限于宿主状态、需求、计时和局部提示；不增加正文副本、预览引擎、Worker 或依赖。提示计时、稳定计时、初始就绪帧、焦点监听和需求有隐藏／销毁清理路径；已有授权且仍有效的异步图片书签可在标签隐藏后提交，但须重新校验会话权限与映射。

## 交接、恢复与目录事务

- 跨窗 prepare 等待组字、待确认输入、图片导入、保存和全文快照任务，然后暂停索引并释放保留的索引快照。commit 成功后目标窗口恢复同一会话及全局位置；持久化失败不会转移任何文档，取消后源窗口重新挂载。源窗口的迟到 detach 不影响新归属。
- v4 工作区新增可选 `documentId`、`globalSelection`、`globalScrollAnchor`。旧草稿仅在会话导入确认后退出热路径，原 draft 保留。恢复失败显示错误并保留引用，不以空文档冒充成功。detach 释放本窗口内存映射而保留磁盘恢复资料；正常标签/模式切换不 detach。跨窗保留活会话历史；卸载后或重启恢复仍按原契约恢复正文和保存点，不承诺恢复撤销栈。
- 原生 `WindowEvent::Destroyed` 补充释放该窗口遗留的会话及快照，等待已有保存结束并保留磁盘恢复资料；已提交交接的文档继续属于目标窗口，不依赖前端销毁回调完成清理。
- 保存冻结完整版本并使用原生编码写出，不再自动补齐尾换行。保存期间继续输入保持脏状态。手动保存可重试未确认事务；错误消息保留原生原因。
- 自动目录只使用完整同版本索引。打开及仅正文编辑不规范化原目录；标题改变后生成不增加撤销步骤的派生事务，保存/导出前物化。目录变化后的历史恢复按磁盘用户事件重放，再派生对应目录，避免将旧字节坐标应用到变化后的目录。

## 增量资源成本与后续边界

每个打开标签增加一个会话协调器和空门面核心，不保留全文 PM 保存基线。挂载块组以约 32 KiB 为分组预算，单个完整结构可超过该分组预算，仍受原有单结构安全预算约束；主动源码模式保留有界窗口，小文档在阈值内渐进挂满。高度和表格布局共用宿主级 2,048 条 / 2 MiB 估算字节缓存，随宿主销毁；不会通过裁剪撤销历史控制缓存。

结构索引仍随正文结构增长。含自动目录且发生相关编辑时，额外保留原始索引及其不可变快照；历史热缓存仍为每会话 64 MiB。目录派生后的撤销会重放磁盘事件，长历史的延迟需要实测。统计/lint 及导出会按需物化完整字符串，统计 Worker 缓存当前活动文档的快照；这部分成本仍需纳入长文内存验收。

剩余优化包括原生捕获期取消、增强渲染的共同可见性调度、全局脚注依赖、结构索引规模治理，以及上述原生交互与资源基准。它们不能由构建或 jsdom 挂载测试代替。

## Markdown 原生搜索与全部替换（2026-10-23 至 2026-10-24）

桌面 Markdown 搜索、精确计数和全部替换由 Rust 文档会话执行。WebView 只传文档身份、修订、查询及选项，保留当前全局命中序号和至多三页结果。TXT/JSON 继续使用原有搜索规则；结构索引、目录物化及导出链路没有随本项迁移。

### 协议与资源

- `markdown_search/matcher.rs` 对不可变快照进行 64 KiB 流式扫描。字面量、非重叠匹配使用现有 `regex` 的 Unicode simple case folding；全词边界单独判断 Letter、Number、下划线，不使用 `\b`。与原 JS `/iu` 共用 Unicode 样本。读取边界保留与查询长度有关的尾段，支持超长查询和跨结构块命中。
- `startSearch` 先返回任务身份，`nomo://markdown-task-progress` 向所属窗口报告进度。所有任务结果携带 requestId、taskId、documentId、baseRevision；先注册监听，再启动，补读一次状态覆盖先完成后响应。扫描中展示阶段计数，完成后才开放完整导航。
- 精确计数不驻留完整命中数组。每任务最多 4,096 个稀疏检查点、128 KiB 预算（当前 16 字节记录实际最多 64 KiB）；全局检查点预算 2 MiB，另限制最多 16 个完成结果，LRU 淘汰。查询匹配器和长查询缓冲另计，不能由检查点预算推导进程内存上限。
- `readSearchPage` 从最近检查点补扫；每页最多 128 条。前端缓存当前页与左右相邻页，最多 384 条，最多三个分页请求同时在途。记录只含序号、UTF-8 安全范围和 CRLF 保留信息。切换查询／选项清零当前序号；正文刷新保持并裁定序号；循环导航沿原开关执行。
- 原生最多两个计算线程，按需启动、空闲退出；分页排到等待队列前端。同一窗口的新查询释放旧任务。扫描逐块、密集命中每 256 次检查取消，进度最多每 100 ms 一次。已进入计算的单次 regex 调用不是可抢占线程。
- 隐藏、切换文档、关闭面板、关闭文档和移交取消任务；关闭／移交等待释放后台工作引用。窗口销毁有原生兜底。源码／语义切换在修订有效时复用结果并重新定位。浏览器内存适配器遵守相同分页契约；桌面失败不退回 JS 全文搜索。

### 替换与历史

`prepareReplaceAll` 在快照上边扫描边构建未发布 PieceTree，新增替换字符串只保存一次，未改正文继续引用原片段。全部替换按原始字面量范围编辑未发布树，因此连续 CRLF 中点命中不需要在前端合成重叠补丁；单次替换仍使用分页返回的安全扩展范围和前后换行保留字符。

正向／逆向历史按至多 4,096 个基本动作、1 MiB 保守字节预算分批写入，同组只对应一次撤销／重做。大范围涉及多个旧片段时拆成有界动作，不展开巨大的旧片段数组。准备期的历史和追加片段只有发布 manifest 后才可达；取消不截断共享日志。撤销／重做逐批应用，恢复逐批重放；组内批次偏移元数据和实际修改形成的 PieceTree 仍随规模增长。取消后不可达磁盘记录留到会话清理，不能声称临时磁盘占用恒定。

准备期间允许编辑。新的输入使已启动任务失效，最终提交还检查 viewGeneration、待确认事务及原生修订。提交前等待组字和草稿，`nativeCommitBusy` 同时接入 PM、CM、全局选区和应用写入入口。候选树、批量日志和保存点比较在发布临界区外完成；最终发布重新检查窗口归属、修订、保存点与 operationId。

无命中或原样替换不增加修订／撤销记录。提交响应丢失仅重试同一 operationId；连续失败后的显式重试可以确认已发布结果，或确认候选释放且版本未变而解除故障门禁，不自动重新执行。已发布后取消或释放失败不能把成功伪装成取消。原生返回有限选区／阅读锚点映射，整版变化使旧异步插入书签失效。

恢复继续遵守已有契约：运行会话内可单步撤销／重做，历史热缓存淘汰不影响它们；卸载或重启后恢复正文和保存点，不恢复旧撤销栈。
