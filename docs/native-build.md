# 原生构建与三平台发布

根目录是单成员 Cargo workspace。crate 为 `nomo-gpui`，二进制为 `nomo`，产品版本只在根 `Cargo.toml` 定义；不通过标签临时改写源码版本。根锁文件保留既有依赖版本。新增直接依赖 `url` 和构建期 `embed-resource` 复用锁文件已有版本，分别用于文件 URL 和 Windows 资源。

## 构建和检查

无文件参数启动进入文档主页；指定文件参数或收到系统文件打开请求时直接打开编辑页。主页左侧保存本地文件夹入口和最近文件，列表项铺满侧栏可用宽度；右侧按最近打开时间显示文档卡片。主页与编辑页共用外壳面板、侧栏宽度和主页导航行；编辑页继续使用连体标签轮廓与有界阴影缓存。添加目录不扫描子树，点击后才进入现有目录工作区；从主页卡片进入编辑页时立即恢复已排队的目录扫描。标题栏右侧 Markdown Mini 小窗旁的“返回主页”按钮或 `Ctrl+Alt+Shift+H`（macOS 为 `Cmd+Alt+Shift+H`）返回主页，已有标签、未保存内容和会话历史继续保留；原版 `Ctrl+Shift+H` 保留给水平分割线。关闭最后一个标签后保留当前文件夹结构和空文档引导，不自动跳到主页。Windows 无参数再次启动由已有进程新建主页窗口；平台重新激活请求唤醒已有工作区，保留当前页面，没有工作区时创建主页窗口。

普通编辑页即使只有一个文档也显示标签栏，文档名和修改状态显示在标签中；缩放与统计使用右下角浮卡，不占用工具栏下方的正文空间。主页和 Markdown Mini 继续隐藏标签栏与统计浮卡。

工作区左侧文件结构树的根目录、文件夹和文件行不显示名称或路径的悬停提示；行内操作按钮仍提供功能说明。

设置窗口由应用内主窗口共享；最后一个主窗口实际关闭后，设置窗口一并关闭并释放控件、订阅及图片连接检查。仍有其他主窗口（含托盘中的工作区）时保留设置窗口；取消关闭或保存失败不会提前关闭设置。单独关闭设置会清理其句柄，下次打开重新创建；NomoMark 开发入口遵循同一关闭规则。

Windows 编辑页的 Markdown Mini 按钮和 `Ctrl+Alt+M` 切换小窗。小窗默认内容区为 460×560、最小 320×240 个逻辑像素；隐藏侧栏、标签、工具栏、大纲与浮动统计，使用单栏语义视图和原版纸面留白。顶部 34px 控制条在悬停或键盘焦点进入时以 140ms 淡入并轻移，提供文件名、修改／外部变更圆点、置顶和返回；尊重系统减少动态效果设置。默认置顶，并通过 Windows Shell 隐藏任务栏按钮，不隐藏或重建窗口。小窗的关闭动作返回正常窗口；退出应用仍走原有未保存确认。

小窗复用活动 DocumentHost、文档会话、窗口预算、撤销历史和阅读锚点；切换不复制完整正文、不写编辑模式设置。进入小窗时回收双栏的非活动 Pane，返回时按原模式按需恢复；小窗尺寸与位置在当前窗口生命周期内记忆，返回恢复原窗口位置、大小与最大化状态。控制条动效只驱动控制条视图，没有常驻计时器；退出时释放控制条、订阅和原生尺寸回调。隐藏的大纲取消查询和交互，保留原有容量限制内的分页与列表位置；返回时只对过期修订刷新。原生尺寸操作结束后同步 GPUI 视口；最大化往返期间临时关闭系统窗口位图拉伸，操作结束恢复原有系统策略。外部文件变化先显示圆点，返回或保存时沿用原有冲突处理。macOS／Linux 原生小窗和全屏内直接切换尚未接入。

2026-10-28 经授权完成 Windows x64、GPUI 0.3.10、100% DPI 的小窗实机验证：普通视口 1280×820、小窗 460×560／最小 320×240；标题悬停、置顶图标切换、拖动／缩放、返回按钮与关闭返回、阅读位置、输入／撤销／重做／保存、四标签、双栏返回，以及含图片／代码／表格／公式／图表的临时文档均实际操作。修复了旧视口宽度残留、悬停控制条不显示、顶部位置跳动、大纲返回重载闪动和最大化过渡拉伸。最终 Release 的最大化往返、明暗主题、控制条返回与 20 轮普通窗口往返复验通过；未将逐次状态观察当作帧率测量。

主页内容区右上角提供“打开文件夹”“打开文件”“新建”，已有标签时还显示“继续编辑”；窄窗口下操作区可换行。“打开文件夹”选择目录后直接进入该目录工作区，并保留主页快捷入口。侧栏“文件夹”分组旁的加号用于仅添加文件夹入口，保持在主页；“最近文档”分组旁也提供同样的小加号，点击后选择并打开文件，复用顶部“打开文件”的行为。刷新与清空最近记录使用“最近打开”栏右侧的图标按钮，并提供说明提示。侧栏使用接近标题栏的中性纯色、低饱和绿色选中态及紧凑行距；Markdown 文件只在显示时隐藏扩展名，其他名称及磁盘路径不变。鼠标悬停在某一条文件或文件夹上时，仅显示该条的移除按钮；按钮绝对定位覆盖行尾，不在隐藏时挤占名称宽度。主页悬停提示只显示名称：侧栏使用对应名称，卡片使用文档标题，不展示完整路径。文档卡片包含固定两行的原生粗体标题区和正文预览，不在卡片下方附加文件名和时间。标题优先取页首标题，缺少标题或尚未加载时显示文件名；标题最多保留 160 个字符，与正文预览共用一次页首读取。

主页数据使用现有 SQLite 依赖，在配置目录的 `document-library.sqlite3` 内保存最多 64 个文件夹入口、200 条最近记录及可再生 PNG 缓存；遵循 `NOMO_DATA_DIR`。移除入口或清空记录不删除原文件。应用内重命名同步记录路径，保存使对应预览失效；回到主页、窗口重新激活及手动刷新时重新校验磁盘内容。未保存的新文档通过“继续编辑”返回，首次保存后进入持久最近列表；启动草稿恢复由文档会话提供，主页自身不管理恢复资料。

正文预览来自磁盘已保存内容的前 32 KiB，固定为 448×384，每张 RGBA 位图约 672 KiB；支持 Markdown 标题、段落、列表、加粗、斜体、删除线、链接色、行内代码、代码块、区分表头的表格、本地图片及预算内的公式／Mermaid。已提取的页首标题不在位图中重复，预览不是完整编辑页面截图。每个文本块最多保留 4000 个字符、256 个样式段，仍受 28 个块和 4096 个解析事件上限约束。每个主页同时执行一个可取消任务，只有实际可见网格行请求预览。图片最多读取两个本地资源（各 8 MiB 输入／16 MiB 解码预算），不主动请求网络图片，超限或失败的资源显示占位。缩略图位图与标题文本合计每窗口上限 24 MiB，PNG 数据总量上限 32 MiB，按最近使用淘汰；离开主页释放位图及 GPU atlas，并取消无用请求。字体库与现有公式／图表共用。阴影仅应用于可见卡片，侧栏为纯色，不使用背景模糊，不创建编辑会话或常驻动画任务。上述字节预算不代表进程或 GPU 总占用；主页视觉、DPI、IME 往返及三轮性能对照仍需实机验收。

缩略图的纸张、文字、代码、表格、公式和 Mermaid 配色跟随应用的目标主题，本地图片保留原色。卡片标题与预览采用文档字体，代码采用等宽字体；Windows 默认正文为 Microsoft YaHei，避免预览把中文交给 Segoe UI 的未指定回退。缓存指纹包含主题配色与字体，切换主题或文档字体会取消旧预览请求、释放旧位图，并按可见范围重新加载；外壳颜色动画不逐帧触发缩略图生成。卡片使用 14px 圆角、中性淡描边和两层柔和阴影，网格边缘预留阴影空间。悬停时描边不变色，卡片在 260ms 内上浮 3px 并展开阴影，移出后用 340ms 回落；按下时用 80ms 轻压，点击仍立即打开文档。底部预留固定入口区域，“打开文档”及右上箭头用 160ms 淡入淡出，不挤压标题或预览。鼠标感应区域覆盖卡片移动前后的位置，快速移入移出从当前状态连续折返。系统减少动态效果时取消位移，短过渡最多 90ms。动效状态仅保存可见卡片的路径和三个短插值，不持有位图或编辑会话；离屏、记录移除、回落完成或离开主页时清理，只有过渡中的可见卡片请求下一帧。预览留在内部边距之内，加载时展示静态骨架，失败时保留可打开文档的卡片和错误说明。上述动效参数尚待原生实机验收。

```sh
cargo check --locked --bin nomo
cargo check --locked --features nomo-mark-demo --all-targets
cargo build --locked --release --bin nomo
cargo build --locked --release --features nomo-mark-demo --bin nomo
cargo test --locked --release --bin nomo
cargo test --locked --release --features nomo-mark-demo --bin nomo
```

指定 `--target` 时产物在 `target/<target>/release/`，否则在 `target/release/`。两种 feature 配置使用同一二进制名：打包脚本始终重新构建默认配置。`--skip-build`／`-SkipBuild` 仅用于已确认默认产物的本地重复打包。

### Windows x64

需要 stable Rust MSVC、Visual Studio C++ Build Tools、Windows SDK、NSIS 3 和 PowerShell 7。脚本会在当前进程中自动加载已安装的 x64 MSVC／SDK 环境，无需先手动打开 Developer PowerShell；已有可用环境会直接复用。`fxc.exe` 和 `rc.exe` 必须可查找；GPUI 也支持进程变量 `GPUI_FXC_PATH`。

在仓库根目录执行：

```powershell
pwsh -File scripts/package-windows.ps1
```

脚本重新构建默认 Release，在 `.artifacts/packages/` 生成 `Nomo_<版本>_x64-setup.exe` 和 `Nomo_<版本>_x64.zip`；版本读取根 `Cargo.toml`。安装包与便携 ZIP 均包含渲染和导出依赖的许可证，卸载器只移除这些已知许可证文件。

安装包使用当前用户范围，复用 `Software\Microsoft\Windows\CurrentVersion\Uninstall\Nomo` 卸载键与旧 InstallLocation。保留快捷方式和“打开方式”，不改写默认程序。卸载仅删除已知文件，不递归删除安装目录或配置。旧版全机／商店安装不属于此 NSIS 升级路径。

打包使用 `dumpbin` 检查实际导入表，随安装包和便携 ZIP 放入工具链 `VCToolsRedistDir` 下的 x64 `vcruntime140.dll`。系统 DLL 由 Windows 提供，运行库依赖发生变化时打包失败并要求更新清单；不从系统目录随意复制 DLL。分发方式参考 [Microsoft 的运行库部署说明](https://learn.microsoft.com/en-us/cpp/windows/determining-which-dlls-to-redistribute?view=msvc-170)。

### macOS arm64

需要完整 Xcode、Metal、Command Line Tools 和 `jq`。

```sh
rustup target add aarch64-apple-darwin
bash scripts/package-macos.sh
```

应用名 `Nomo.app`、标识 `com.nomo.desktop`，最低系统版本元数据保持 12.0。使用 ad-hoc 签名，签名或校验失败终止打包；不包含公证和 Quick Look。`.app` 同时保留于输出的任务 staging 目录。

### Linux x64

CI 使用 Ubuntu 24.04，构建和打包依赖如下：

```sh
sudo apt-get install clang libclang-dev cmake pkg-config libssl-dev \
  libfontconfig1-dev libfreetype6-dev libxkbcommon-dev libxkbcommon-x11-dev \
  libwayland-dev libxcb1-dev libxcb-xkb-dev libxcb-randr0-dev \
  libxcb-xinput-dev libxcb-cursor-dev libvulkan-dev libegl1-mesa-dev \
  libasound2-dev libudev-dev fonts-noto-cjk xdg-desktop-portal \
  dpkg-dev rpm desktop-file-utils jq
bash scripts/package-linux.sh
```

包包含桌面入口、图标、许可证和样本；保留 X11／Wayland。直接动态依赖由 `dpkg-shlibdeps`／RPM 扫描，另外声明运行时加载的图形、字体和桌面库。Ubuntu 24.04 二进制不承诺兼容更旧 glibc；RPM 仍需目标发行版安装验证。

## 发行契约

输出目录为 `.artifacts/packages/`，staging 为 `.artifacts/package-work/`。脚本不自动安装应用或清理用户目录。

| 平台 | 文件名（VERSION 来自 Cargo） |
|---|---|
| Windows | `Nomo_VERSION_x64-setup.exe`、`Nomo_VERSION_x64.zip` |
| macOS | `Nomo_VERSION_aarch64.dmg`、`Nomo_aarch64.app.tar.gz` |
| Linux | `Nomo_VERSION_amd64.deb`、`Nomo-VERSION-1.x86_64.rpm` |

分支推送、PR 和手动 workflow dispatch 仅构建、检查并上传工作流产物。只有推送匹配 Cargo 版本的 `v*.*.*` 标签才发布，且必须存在对应发布说明。

三平台全部成功后，验证六类资产及归档结构、生成 `checksums.md5`，上传草稿 Release，最后转为公开。已公开的同名 Release 不允许覆盖。稳定版继续更新 Homebrew；下载站使用既有部署钩子，不在本次工作中触发。

上述资产名已对照 v0.6.2 正式 Release，RPM 包身份保持 `nomo`。预发布标签仍可使用：资产名保留完整 Cargo 版本，Linux 包内部以 `~` 表示预发布，macOS bundle 数字版本取主／次／补丁段。

## 数据和功能边界

配置目录沿用旧版：Windows `%APPDATA%/com.nomo.desktop`、macOS `~/Library/Application Support/com.nomo.desktop`、Linux `~/.local/share/com.nomo.desktop`。JSON 未知键保留，设置通过原子替换写入，不清理旧文档、快照或缓存。

偏好设置按固定参考版 `339fb932` 保留通用、编辑器、外观、文件与窗口、图片、统计与大纲、高级、关于八个分区的顺序和布局。外观页使用四张明暗主题预览、字体输入与恢复按钮；统计类型为两行分段控件；快捷键回到高级页；关于页保留版本徽标、产品说明、项目链接和更新区。窗口宽度不超过 760 个逻辑像素时收起导航文案，设置项改为上下排列。

设置页的按钮、标签、说明和显隐条件以参考版为准，不增加目录入口、信息圆标、预览角标或常驻能力说明。初始窗口恢复为 860×620、最小窗口 760×520 个逻辑像素。原版已有的主题导入／导出、字体恢复、项目链接、文件关联与更新按钮保留；图片连接测试不额外附加状态徽标。

设置项按当前接线范围开放：未接通项保留原位置并禁用，原因仅通过已有标签或控件的悬停提示说明；主题只启用当前已接通的 Nomo 默认配色。自动清理、文件关联、渲染后端切换等未接通项不注册对应写入或外部动作。打开位置偏好、Windows 关闭到托盘、自动与手动检查更新已接通；更新下载交给浏览器，不执行安装器。外部变更使用确认弹窗，自动处理策略偏好仍禁用。图片页按已保存的上传策略展开可编辑的 PicGo / PicGo-Core 参数，并提供显式连接检查；图片选择、粘贴和拖放使用所选策略。未知旧配置保持原值，自定义快捷键保留只读状态。上传服务及真实桌面输入仍需另行验收。

本次界面恢复的增量资源为静态主题预览令牌、三个小型内嵌 SVG 和文本设置的少量校验结果；专属页面只在选中分区时构造，禁用输入不创建实体或订阅。开关动效只在变化期间请求绘制，分区切换和窗口关闭时释放对应状态；不新增正文副本、系统字体列表缓存、依赖或常驻任务。构建检查与实机逐页视觉、DPI、交互验收分别记录，后者仍待执行。

导出、Quick Look、MSIX／Shell 扩展尚未接入。默认 Workspace 与开发入口共用窗口化 NomoMark 和文档会话，feature 仅控制开发外壳，差距见 Roadmap。SQLite、编码、搜索及 Emoji 等沿用已锁定依赖，现由默认构建链接；没有新增依赖版本。

隔离验收可设置进程变量 `NOMO_DATA_DIR` 为任务专用目录；配置、会话和保存前快照均落入该目录。未设置时沿用既有平台数据目录。该变量不修改系统环境，不用于默认安装或迁移用户数据。

保存与删除确认框使用 `339fb932` 的 `UnsavedConfirmDialog`／`ConfirmDialog` 布局，由 GPUI `set_prompt_builder` 在窗口内绘制。保存框保留保存、放弃修改、取消三按钮和窄窗口纵向排列；删除框保留路径详情、左侧取消和右侧删除。动作返回值独立于显示顺序；Esc 与遮罩点击取消，Tab／方向键切换按钮，Enter／空格执行当前选择，关闭后恢复原焦点。打开、保存、选目录及图片选择仍使用系统文件选择器，文档正文、撤销历史和窗口加载方式不变。

普通无参数冷启动进入主页；Windows 无参数再次启动通过实例通信让已有进程新建主页窗口，保留原窗口及文档，保持单进程多窗口。带文件参数的启动通过同一用户数据目录、同一 Windows 会话的实例锁和原生消息窗口转交绝对路径，随后执行应用内窗口策略；平台 reopen 仅唤醒已有工作区，没有工作区时创建主页窗口。`NOMO_DATA_DIR` 隔离实例，NomoMark 开发入口不参与实例转交。消息上限 128 KiB、单批 64 个路径、接收队列 8 批，只有接受请求后第二实例才退出；失败明确提示，不自动启动独立副本。消息窗口在 `WM_NCCREATE` 保存回调上下文后继续默认初始化，使窗口名称可供第二实例查找。每个普通主实例持有一个消息监听线程和不可见消息窗口，空闲时阻塞等待消息，随应用退出释放；新窗口复用应用共享的文档服务及资源缓存。

菜单、主页、最近记录、文件树和本地 Markdown 链接共享已打开／正在打开文档的跨窗口归属检查。文件树和链接保留当前窗口优先策略；显式菜单和系统打开沿用窗口设置。每个工作区最多排队 64 个打开意图，只保存路径、锚点和代次；批量请求先等待输入收尾，再逐个推进，较早加载结果可以成为后台标签，但不覆盖后来的前台选择。锚点定位、重载位置及另存草稿绑定目标文档，在激活成功后执行。

主页不自动显示草稿恢复框。应用共享恢复列表，只在活动工作区打开对应文件后提示一次；未命名草稿、稍后处理的草稿和无法自动核实的资料，可通过“文件 → 恢复未保存文档”再次进入。列表显示文件名与相对时间；另存草稿先作为独立未命名文档恢复，保留已打开的原文件。使用磁盘版本成功后才清理旧草稿；放弃未命名草稿另行确认，删除与恢复同用路径操作锁，已挂载的会话不能被恢复清理删除。

恢复发现只读比较会话与保存点，排除已保存或撤销回原内容的资料，不重写旧历史。扫描按原有上限保留 32 个候选，每进程目录最多检查 256 个子项；恢复元数据和保存意图限 1 MiB，历史日志检查限 32 MiB，单条历史和保存点限 8 MiB，最多重放 65,536 个事件，正文比较缓冲为 64 KiB。超过检查预算或校验失败的资料保留在手动列表，不自动提示。扫描顺序执行、无热历史缓存，应用退出取消扫描；不改变正式会话的撤销历史或正文驻留预算。
